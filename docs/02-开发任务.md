诊断流程结构化与可控化。

## 一期 Now

### G-01：统一领域契约

定义并测试 Case、Material Manifest、Evidence Ledger、Conclusion 和 Node Event。Graph State
只传递稳定字段，节点内部临时数据不得成为跨节点隐式依赖。

### G-02：材料门禁与条件边

加入 `material_gate`。材料为空、403、路径不可用或关键时间窗缺失时，不进入归因节点，转入
`need_human` 或 `insufficient_data`。

### G-03：持久化 Checkpointer

替换默认 `MemorySaver`，验证进程重启后根据同一 `thread_id` 恢复。Case 状态和 Graph
checkpoint 分别持久化，禁止互相冒充。

### G-04：人工中断与恢复

使用 LangGraph `interrupt/resume` 接收用户补充文本和附件，恢复后跳过已经完成的材料采集。

### G-05：信号扫描与诊断路由

从分析节点拆出 `signal_scan` 和 `diagnosis_route`，根据可信错误码走错误码 Playbook，否则走
现场症状路线。路由必须可解释并写入事件。

### G-06：证据归并

所有路线写入只追加 Evidence Ledger；`evidence_reduce` 处理重复、冲突和缺失证据，输出统一
Conclusion。

### G-07：可观测性

记录节点开始/结束、耗时、重试、错误、输入输出摘要和路线选择。敏感材料不得进入普通日志。

### G-08：Case 回放评测

至少准备三类匿名化 fixture：错误码成功、无错误码成功、材料不足/冲突。比较兼容基线和
graph-v1 的路线、证据、结论状态与人工介入率。

## Later

- LangSmith 或 OpenTelemetry 接入；
- 多 Worker 并发和队列升级；
- 错误码因果图；
- 更多无错误码专项路线；
- 诊断闭环统计和知识反哺。

## 明确不做

- Claude CLI/ttyd 运行时；
- 多 Agent 自由协作、辩论或仲裁；
- `origin-split` 等中间公开版本；
- 自动修改机器人配置、重启服务或执行修复。
