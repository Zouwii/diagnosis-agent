# 615038 地图数据读取错误

## jstate
`error/nav-net/get_map_data_failed`

## 错误解释
nav-net 调用 `/map_master/get_current_map_info` 服务失败，无法获取地图数据。

## 等级
level5（错误）

## 映射推理依据

nav-net 错误码不走 nav-manager 的 `abnormal_ids.h / health_monitor.cpp`，独立模块直接报 jstate。

| 步骤 | 文件 | 内容 |
|------|------|------|
| ① 错误码注册 | `jcar3-params/codes/s3_errors.yaml` | `615038: name: error/nav-net/get_map_data_failed` |
| ② 源码 grep | `grep -rn "get_map_data\|get_map_info" nav-net/` | 命中 `robot_state.cpp:605 getMapInfo()` |
| ③ 触发逻辑 | `robot_state.cpp:610` | `callService(map_srv, get_map_info_, 3)` 重试3次失败 → return false |

> 推理：`getMapInfo()` 服务调用失败 → nav-net 直接通过 LOG_ERROR + jstate 上报 → jstate 用①查表 → 615038。

## 触发条件（代码分析）

### robot_state.cpp:605-620 — getMapInfo()
```cpp
bool RobotState::getMapInfo(nlohmann::json& map_info) {
  bool ok = callService(map_srv, get_map_info_, 3);   // 最多重试3次
  if (!ok) {
    LOG_ERROR << "get map info from /map_master/get_current_map_info failed";
    return false;
  }
  map_info = nlohmann::json::parse(map_srv.response.message);
  if (!map_info.contains("edges")) return false;
}
```

## 常见原因
1. `/map_master/get_current_map_info` 服务不可用
2. 地图 JSON 格式错误或缺少 edges 字段
3. nav-net 与 map_master 通信超时（重试3次后失败）

## 排查思路

### Agent：日志排查
1. 查看 nav-net 日志，关键字 `get map info from /map_master`、`failed`
2. 接口返回错误 → 联系地图维护；返回正常但 nav-net 调用失败 → 联系 nav-net 维护

### Agent：Bag 排查（rostopic/rosservice 等只读操作）
1. 检查服务存活：`rosservice list | grep get_current_map_info`
2. 手动调用服务验证：
   ```bash
   rosservice call /map_master/get_current_map_info "data: '[\"map_png_info\"]'"
   ```
3. 检查返回 JSON 是否包含 `edges` 字段且可正常解析
