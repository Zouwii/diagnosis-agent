### abnormal_check.cpp:192 — qrcodeCheck()
```cpp
bool AbnormalCheck::qrcodeCheck(const int loc_type) {
  if (loc_type != LocType::HETEMAP) return true;  // 非二维码模式跳过
  if (!ros_datastore_->visualMarks(msg)) return false;
  if (std::stoi(msg.landmarks[0].id) > -1) {
    diff_t = now - msg.header.stamp;
    return (diff_t.sec < 1);  // 数据超过1秒即判定丢失
  }
  return false;
}
```

## 常见原因
1. 相机被遮挡、脏污或角度偏移
2. 二维码破损、未贴或位置变动
3. 相机曝光度不足导致识别失败
4. `/visual_marks` topic 数据延迟 > 1秒
5. 机型定位模式设置非 HETEMAP

## 排查思路

### Agent：日志排查
1. 查看 nav-manager 日志，关键字 `qrcodeCheck`、`visualmarks id is not detected`

### Agent：Bag 排查（rostopic/rosservice 等只读操作）
1. `rostopic echo /visual_marks` 检查是否有稳定数据输出，观察时间戳延迟
2. 检查当前定位模式：`rosparam get /nav_manager/loc_type`（应为 HETEMAP）

### 人员操作
（需要到现场/物理介入的事项）
1. 检查地面二维码是否完整、有无破损或污损
2. 确认二维码位置是否与地图像素位置一致，是否被遮挡
3. 检查相机镜头是否有灰尘、水雾，安装角度是否偏移
4. 检查环境光照是否发生明显变化

### 需要人工审核的行为
1. 修改相机曝光度参数
2. 切换定位模式
