# 开发指南

## 本地运行

```bash
cp .env.example .env
pip install -r requirements.txt
python -m uvicorn server.main:app --port 6001 --reload

# 另一个终端
python -m server.worker
```

## 测试

```bash
pytest -q
```

测试必须覆盖：

- `origin-v1` 单节点兼容拓扑；
- `graph-v1` 节点和条件边；
- 两版本冻结 Case 行为一致性；
- 四类 mode 参数和采集边界；
- 租户隔离、路径穿越和报告路径；
- Worker 领取、失败和终态不重复执行。

手工网络探测脚本不得命名为 `test_*.py`，也不得在 import 时直接调用外部模型。

## 修改 Graph

图定义位于 `agent/graph.py`：

```text
origin-v1: START → diagnosis_cli → END
graph-v1:  START → collect → analyze → report → END
```

新增节点时：

1. 在 `agent/nodes/` 中实现只依赖领域输入输出的节点；
2. 在 `DiagnosisState` 中增加稳定字段；
3. 在 `agent/graph.py` 中接线；
4. 增加节点单测、条件边测试和恢复测试；
5. 用冻结 Case 验证兼容语义。

不要修改 `origin-v1` 来承载新功能。

## 添加来源模式

1. 更新 `engine/mode_registry.py` 白名单；
2. 更新 `CreateCaseRequest.mode`；
3. 在 `engine/collectors/dispatch.py` 接入只读采集器；
4. 增加参数、租户路径和采集失败测试。

客户端不能传 Python 类名、任意 Skill 名称或 shell 命令。

## 部署

```bash
bash onekey-deploy.sh
```

生产配置至少包括 `DIAGNOSIS_STORAGE_ROOT`、management-system 地址、内部 Token、允许来源和
持久化 checkpoint 数据库。默认运行版本是 `graph-v1`。

## 常见问题

- Worker 不处理：确认 API 与 Worker 使用相同 `DIAGNOSIS_STORAGE_ROOT`。
- SSE 无进度：检查 Case 的 `progress_events` 是否持续持久化。
- 本地路径被拒绝：路径必须位于当前租户上传目录或 management-system 工作区。
- 恢复无效：确认配置了持久化 checkpointer，`MemorySaver` 只适合本地基线。
